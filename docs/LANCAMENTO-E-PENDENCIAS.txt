2. FLUXO DE RELEASE
-------------------
  1. Atualize a versao em apps/desktop/src-tauri/tauri.conf.json (e nos Cargo.toml, se mudar).
  2. Commit na main com o CI verde.
  3. Crie a tag IGUAL a versao, com "v" na frente:   git tag v0.1.1 && git push origin v0.1.1
  4. O workflow release.yml: confere tag x versao, compila NSIS e MSI, assina, gera o .sig e o
     latest.json, e publica o GitHub Release com o changelog automatico.
  5. Os apps instalados veem a versao nova ao abrir ou em ate 6 horas.
  6. Antes de cada release, execute e registre o checklist manual (docs/QA-CHECKLIST.md).


3. REGRAS DO PROJETO
--------------------
  Atualizacao
  - O app NUNCA instala atualizacao sozinho; so oferece.
  - Com controle conectado, instalar exige confirmacao do usuario (o backend recusa sem ela).
  - O instalador nao apaga os dados; so apaga se o usuario marcar a opcao ao desinstalar.
  - O usuario pode desligar a procura automatica em Configuracoes > Sobre.

  Seguranca
  - Segredos (chaves, tokens, senhas) nunca vao para o repositorio nem para logs.
  - A chave privada do updater so existe na sua maquina e no segredo do CI.
  - Pacote UDP sempre autenticado (AEAD); nada de dispositivo nao pareado.

  Protocolo (formato no fio, ja no nome novo)
  - Magic do pacote UDP: "VP" (bytes 56 50).  Broadcast de descoberta: "VPDISC1".
  - URI de pareamento: vynpad://   Servico mDNS: _vynpad._tcp
  - Mudou o protocolo? Regenere os vetores (pnpm --filter @vynpad/protocol gen) e o app Kotlin
    deve passar nos MESMOS vetores (protocol/test-vectors).

  Qualidade (antes de qualquer commit/push; sao os mesmos comandos do CI)
    cargo fmt --all --check
    cargo clippy --workspace --all-targets --locked -- -D warnings
    cargo test --workspace --exclude vynpad-desktop --locked
    cargo test -p vynpad-desktop --locked
    cargo deny check
    pnpm format:check ; pnpm lint ; pnpm typecheck ; pnpm test
    pnpm --filter @vynpad/protocol check
  - Mudou comando, evento ou tipo em Rust?  UPDATE_BINDINGS=1 cargo test -p vynpad-desktop bindings_ts
  - Mudou query do sqlx?  scripts/sqlx-prepare.sh

  Fluxo de trabalho
  - Uma task por vez; cada task fecha com commit proprio (feat(...): ... (T-xxx)).
  - Mensagens de commit em portugues, no padrao conventional commits.
